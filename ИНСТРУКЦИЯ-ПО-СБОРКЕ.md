# FlickerVPN 4.12.0 — инструкция по сборке в Android Studio

Пакет: **FlickerVPN-4.12.0-src.zip** — исходники с полностью перенесённым
обходом DPI из ByeByeDPI-x-tg v1.0.1-build5 (что именно перенесено —
`DPI-INTEGRATION.md`). Всё необходимое для сборки уже внутри:

| Компонент | Где лежит | Откуда |
|---|---|---|
| Go-ядро sing-box | `android/app/libs/flicker-core.jar` + `android/app/src/main/jniLibs/arm64-v8a/libflickerbox.so` | восстановлено из рабочего APK (Go-тулчейн НЕ нужен) |
| byedpi 17.3 (обход DPI) | `android/app/src/main/cpp/byedpi/` + `native-lib.c` | дословно из ByeByeDPI-x-tg (commit e0fccf68) |
| tun2socks | `android/app/src/main/jni/hev-socks5-tunnel/` | дословно из ByeByeDPI-x-tg |
| TG WS-прокси | `android/app/src/main/tglibs/*/libtgwsproxy.so` | готовый бинарник |
| Тестовый ключ подписи | `keys/flicker-release.jks` (пароль/alias: `flicker`) | только для release-сборки |

---

## 1. Требования (поставить ровно эти версии)

1. **Android Studio Ladybug 2024.2.1 или новее** (AGP проекта — 8.7.3).
2. В Studio: **Settings → Languages & Frameworks → Android SDK**:
   * вкладка **SDK Platforms**: **Android 15 (API 35)**;
   * вкладка **SDK Tools** (включить «Show Package Details»):
     * **NDK (Side by side) → 27.2.12479018** ← именно эта версия, ~1 ГБ;
     * **CMake → 3.22.1**;
     * Build-Tools 34.0.0 (обычно уже есть).
3. JDK не ставьте отдельно — встроенный **jbr-17** Studio подходит
   (проверка: Settings → Build Tools → Gradle → Gradle JDK = 17).
4. Свободное место: ~10 ГБ (NDK + Gradle-кэши + сборка).
5. Интернет для первого Gradle Sync (скачает Gradle 8.9 и androidx-зависимости).

На Linux/macOS можно запустить самодиагностику: `bash check-env.sh` (из корня
проекта) — проверит JDK, NDK, CMake и доступность зеркал.

## 2. Открыть проект

Распакуйте архив и в Android Studio выберите **Open** → папку:

```
FlickerVPN-4.12.0/android        ← ВАЖНО: именно android/, не корень архива!
```

(Gradle-проект — `settings.gradle.kts` — лежит в `android/`.)

Дождитесь окончания **Gradle Sync** (первый раз 3–10 минут). В логе sync
должна быть строка `[core] ядро: flicker-core.jar … + arm64-v8a/libflickerbox.so`.

## 3. Собрать debug-APK (для проверки на телефоне)

**Build → Build App Bundle(s) / APK(s) → Build APK(s)**.

Что при этом происходит автоматически (ничего запускать руками не нужно):

1. Задача **`runNdkBuild`** (висит на preBuild) собирает ndk-build'ом
   `libhev-socks5-tunnel.so` → `android/app/src/main/hevlibs/arm64-v8a/`;
2. **CMake** (`externalNativeBuild`) собирает `libbyedpi.so` из `cpp/`;
3. Kotlin/Java компилируются, всё пакуется в APK.

Результат: `android/app/build/outputs/apk/debug/app-debug.apk`.

Debug-пакет ставится как отдельное приложение `dev.flicker.vpn.debug` —
можно держать рядом с обычным FlickerVPN.

### Проверка APK перед установкой (обязательно!)

В Studio: **Build → Analyze APK…** → откройте `app-debug.apk`:

* вес **24–28 МБ** (меньше 10 МБ — ядро не попало, не ставьте);
* в `lib/arm64-v8a/` должны лежать **четыре** библиотеки:

```
libflickerbox.so          (~62 МБ несжатой)  — sing-box, VPN-серверы
libbyedpi.so              (~100 КБ)          — обход DPI          ← НОВОЕ
libhev-socks5-tunnel.so   (~1 МБ)            — tun2socks обхода   ← НОВОЕ
libtgwsproxy.so           (~2 МБ)            — Telegram-туннель
libjnidispatch.so                            — мост JNA
```

Если `libbyedpi.so`/`libhev-socks5-tunnel.so` нет — см. раздел 6.

## 4. Установка и проверка обхода DPI на телефоне

1. Скопируйте APK на телефон, установите (разрешите «неизвестные источники»).
2. **Выключите другие VPN-приложения** (включая ByeByeDPI-x-tg): в Android
   работает только один VPN, два вместе = чёрная дыра для трафика.
3. Откройте FlickerVPN → нажмите кнопку режима **«Обход DPI»**.
4. Нажмите **«Подключить»** → системный диалог согласия VPN → **OK**.
5. Ожидаемый результат:
   * статус: **«Подключено: Обход DPI · Эталон ByeByeDPI-x-tg (дословно)»**;
   * уведомление в шторке «VPN · Обход DPI · …» с кнопками Пауза/Отключить;
   * ключик VPN в статусбаре;
   * ранее блокировавшиеся сайты открываются.
6. Если сайт не открылся: тап по кнопке режима (при включённом обходе) →
   диалог стратегий → **«Подобрать автоматически»** — приложение переберёт
   пресеты byedpi и оставит рабочий. Можно также задать «Свою строку» —
   формат из эталона, например: `-Kt,h -o1 -e97 -An -Ku -a1`.
7. Быстрая проверка VPN-серверов и TG-туннеля (они не менялись): режим
   «VPN» → список узлов → «Подключить»; экран Telegram-туннеля — как раньше.

## 5. Release-сборка (подпись)

Создайте `android/local.properties` (файл не коммитится):

```properties
sdk.dir=<путь к Android SDK — Studio создаст сама>
FLICKER_KEYSTORE_FILE=../../keys/flicker-release.jks
FLICKER_KEYSTORE_PASSWORD=flicker
FLICKER_KEY_ALIAS=flicker
FLICKER_KEY_PASSWORD=flicker
```

Путь к keystore считается от `android/app/`, поэтому `../../keys/` — это
`keys/` в корне проекта. Затем:

```bash
cd android
./gradlew :app:assembleRelease
# Windows: gradlew.bat :app:assembleRelease
```

Результат: `android/app/build/outputs/apk/release/app-release.apk`.

⚠️ `keys/flicker-release.jks` — **тестовый** ключ из архива. Для раздачи
людям создайте свой (`keytool -genkeypair …`) и укажите его там же; иначе
обновление поверх вашей сборки сможет выпустить кто угодно, владеющий этим
файлом. При установке поверх старой версии, подписанной другим ключом, старую
нужно сначала удалить.

## 6. Troubleshooting

| Симптом | Причина / лечение |
|---|---|
| Sync: `NDK not configured` / `No version of NDK matched` | Не установлен NDK **27.2.12479018**: SDK Manager → SDK Tools → Show Package Details → NDK (Side by side) → отметить 27.2.12479018 |
| Ошибка `runNdkBuild` (Process 'ndk-build' finished with non-zero…) | Смотрите вывод задачи в Build-окне. Частое: не установлен NDK той же версии; на Windows — антивирус блокирует `ndk-build.cmd`. Полный лог: `gradlew :app:runNdkBuild --stacktrace` |
| `CMake 3.22.1 not found` | SDK Tools → CMake → поставить галочку на 3.22.1 |
| Gradle sync упал с «НЕ НАЙДЕНО ЯДРО» | В архиве ядро есть (`app/libs/flicker-core.jar`). Ошибка означает, что открыли не папку `android/` или файл потерялся при распаковке |
| `OutOfMemoryError` на packageRelease | В `android/gradle.properties` поднимите `-Xmx3072m` до `-Xmx4096m` |
| Приложение пишет «Библиотеки обхода DPI не загружены: …» | В APK не попали .so обхода — проверьте раздел 3 (Analyze APK); пересоберите с установленными NDK/CMake |
| Обход подключается, но интернет пропадает | Другое VPN-приложение всё ещё включено; или провайдеру не подходит дефолтный пресет — запустите «Подобрать автоматически» |
| «establish() вернул null» | Системное согласие VPN не дано (диалог отменили) или VPN перехвачен другим приложением — выключите чужие VPN и подключитесь заново |
| Странные ошибки кэша после правок | `cd android && rm -rf .gradle app/build` (Windows: удалить папки) и пересобрать; либо выключить `org.gradle.configuration-cache` в gradle.properties |

Полезные файлы с подробностями: `BUILD-ANDROID.md` (сборка, §1.5 — про
нативные библиотеки обхода), `BUILD-NOW.md` (быстрый путь),
`DPI-INTEGRATION.md` (что именно перенесено из ByeByeDPI-x-tg и почему
прежний обход не работал), `README-OFFLINE.md` (сборка при плохом интернете).

## 7. Сборка из терминала (без Studio, эквивалент)

```bash
cd android
./gradlew :app:assembleDebug       # или gradlew.bat на Windows
# NDK и CMake должны быть установлены (sdkmanager или через Studio)
```
